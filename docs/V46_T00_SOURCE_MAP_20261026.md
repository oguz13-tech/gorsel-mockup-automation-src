## Read-only fail-closed preflight

Before any future runtime operation, the candidate must:

1. Resolve an explicit workspace root and reject an empty/missing root.
2. Refuse to treat the code root as a production data root.
3. Verify source identity and approval state before pixel processing.
4. Refuse writes to original pools, backups, SQLite, WAL/SHM, and historical
   outputs.
5. Write only to an isolated review/output root, using temporary files followed
   by atomic publication.
6. Emit a failure rather than silently creating an empty replacement pool.

## Rollback recipe

1. Stop the candidate process using its verified process identity.
2. Preserve the checkpoint commit and its test output.
3. Remove only the isolated review/output directory created for the run; never
   remove source, backup, database, or historical-output locations.
4. Revert the candidate branch by a new explicit revert commit if required;
   never use force-push, hard reset, or destructive cleanup.
5. Re-run the read-only preflight and database integrity checks before retrying.
